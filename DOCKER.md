# Docker runtime

Use [DEPLOYMENT.md](DEPLOYMENT.md) for the complete home-server walkthrough and [docs/CONVEX_SETUP.md](docs/CONVEX_SETUP.md) for backend setup.

The Dockerfile builds a Node.js 22 / Next.js standalone image, runs as a non-root user, and accepts its public Convex API URL at runtime. It does not embed deployment credentials or copy the entire development dependency tree into the runner.

| Setting | Where | Meaning |
| --- | --- | --- |
| `NEXT_PUBLIC_CONVEX_URL` | Compose `.env` | Browser-reachable Convex API origin |
| `CONVEX_URL` | Web runtime | Optional override; preferred for manually running a portable image |
| `APP_PORT` | Compose `.env` | Host port; default 3000 |
| `SITE_URL` | Convex deployment | Exact public app origin, including scheme and port |
| `JWT_PRIVATE_KEY`, `JWKS` | Convex deployment | Generated by Convex Auth setup |
| `RESEND_API_KEY`, `SMTP_FROM` | Convex deployment | Optional password-reset email delivery |
| `SECRETS_ENCRYPTION_KEY` | Convex deployment | Optional encrypted AI/provider credentials |

The container speaks HTTP; use a reverse proxy for HTTPS. `/api/config` exposes only the public backend URL and disables caching. `/api/health` returns 503 for a missing/invalid URL and 200 when the web process is configured. Neither endpoint reports backend connectivity or exposes secrets.
